# Ключевые решения

## 2026-11-04 — Основа проекта

- **Сервер — Node.js + Express 5, база — SQLite (better-sqlite3).** Один файл
  базы в `data/`, не нужен отдельный сервер БД — проект запускается двумя
  командами.
- **Одна таблица `users` для студентов и сотрудников** с полем `role`
  (`student` / `staff`). У студента заполнены направление, курс и группа,
  у сотрудника — должность. Так проще проверять права в одном месте.
- **Пароли — только хеш bcrypt.** При входе с несуществующим логином пароль
  всё равно сверяется с «пустым» хешем, чтобы по времени ответа нельзя было
  узнать, есть ли такой логин. Не больше 10 неудачных попыток с одного
  адреса за 15 минут.
- **Сессии — express-session**, cookie `httpOnly`, `sameSite=lax`, живёт
  8 часов; при входе сессия создаётся заново. Пока сессии хранятся в памяти
  сервера: после перезапуска нужно войти снова (для прототипа это нормально).
- **Права проверяются на сервере** (`src/access.js`). Студент видит только
  свой профиль; сотрудник деканата — профили студентов. На чужой и на
  несуществующий id студент получает одинаковый ответ «Нет доступа», чтобы
  нельзя было перебором узнать, какие id заняты.
- **Защита от внедрения скриптов:** данные выводятся только через
  `textContent`, плюс заголовок Content-Security-Policy запрещает скрипты
  со сторонних сайтов и встроенные скрипты.
- **`.env` читается встроенной возможностью Node** (`--env-file-if-exists`),
  без отдельной библиотеки dotenv.
- **Шрифты — системные**, без загрузки извне: нет вопросов с лицензиями,
  страница открывается быстрее. Логотип — собственный (щит с книгой).

## 2026-11-04 — Расписание

- **Каждое занятие хранится отдельной строкой с конкретной датой**, а не
  шаблоном «каждый вторник». Так перенос, замену или отмену легко показать:
  у занятия меняется статус, а старые значения (дата, пара, аудитория,
  преподаватель) сохраняются рядом в полях `old_*`.
- **Время — по номеру пары.** В базе хранится номер пары (1–8), а время
  звонков задано в одном месте — `src/pairs.js`. Пары по 80 минут, как в
  МГИМО: 9:00–10:20, 10:35–11:55, обед, 12:55–14:15, 14:30–15:50 … до
  8-й пары 20:30–21:50. На некоторых факультетах (ФМО) 3-я пара раньше —
  12:10–13:30, а обед после неё. Поэтому у каждой группы записан факультет
  (таблица `groups`), и по нему выбирается расписание звонков.
- **Отдельные таблицы дисциплин и преподавателей** — их же будем
  использовать в разделе «Успеваемость».
- **Переносы пока только в данных `seed`** (по одному примеру каждого вида
  на текущей неделе для каждой группы). Кабинет сотрудника для правки
  расписания — позже, если останется время: в обязательном ядре от
  сотрудника требуется работа с заявками.
- **Студент видит только расписание своей группы**: группа берётся из его
  профиля на сервере, параметр `?group=` в адресе для студента
  игнорируется. Сотрудник может выбрать любую группу.
- **Перенесённое занятие видно в двух местах**: на новом месте — цветной
  карточкой «Перенесено, было: …», на старом — пунктирной «Перенесено
  на …», чтобы студент не потерял пару.
- **«Сегодня» считается по московскому времени**, независимо от часового
  пояса сервера.
- **Изменения выделяются не только цветом, но и подписью** («Отменено»,
  «Другая аудитория») — понятно и людям, которые плохо различают цвета.

## 2026-11-04 — Успеваемость

- **Понятные названия вместо кодов Б1/Б2/Б3:** «Работа в семестре» (Б1),
  «Сессия» (Б2), «Общественная активность» (Б3) и «Надбавка» с
  расшифровкой, за что она начислена: волонтёрство, спортивная секция МГИМО
  или научная работа, а также сколько баллов и когда.
- **Никакого «Нет данных».** У каждой оценки есть статус, который сайт
  вычисляет сам: «Выставлено 30 октября», «Ожидается до 19 декабря» или
  «Срок прошёл — обратитесь в деканат» с кнопкой «Написать в деканат».
  Для этого у каждой дисциплины в базе записаны сроки (`current_due`,
  `result_due`).
- **Условная формула рейтинга** (точная формула МГИМО нам неизвестна):
  работа в семестре до 40, сессия до 50, общественная активность до 10,
  надбавка сверху до +10. Пока выставлено не всё, рейтинг помечен как
  «Предварительный». Все правила — в одном файле `src/rating.js`.
- **Сводка «Как у меня дела» на одном экране:** вывод одной фразой (долги,
  просроченные оценки или «всё идёт по плану»), крупное число рейтинга,
  полоски по частям рейтинга, ближайший срок и итог прошлого семестра.
- **Два семестра в демо-данных:** весенний 2025/26 закрыт (у одного
  студента там долг), осенний 2026/27 идёт. Даты считаются от текущего
  учебного года.
- **Права:** студент видит только свои оценки (id берётся из сессии,
  параметр `?student=` игнорируется). Сотрудник может только смотреть
  оценки студентов, но не менять их.
- **«Написать в деканат» пока ведёт на заглушку** `/contact`, куда
  подставляется тема обращения. Когда появится раздел заявок, заглушка
  станет формой с заполненной темой.

## 2026-11-04 — «Набрано на сегодня» вместо пугающего рейтинга

- В ноябре рейтинг «29,1 из 100» пугал студента, хотя оценки у него хорошие:
  невыставленное считается как 0. Теперь, пока семестр идёт, крупно
  показывается **«Набрано на сегодня: X из Y возможных»** и процент, где
  Y — максимум только по уже выставленному. Надбавка указана отдельно.
- Рейтинг из 100 остаётся, но мелкой строкой ниже, с пометкой
  «предварительный».
- Полоски частей рейтинга показывают три уровня: набрано (тёмная часть),
  сколько можно было набрать на сегодня (светлая) и максимум за семестр
  (вся полоса). Под ними подпись-легенда.
- Когда всё выставлено, экран показывает итоговый рейтинг из 100, как раньше.
